# Release Desk · 产品发布工作台

这是 DeepSeek SuperAgent 教程的公开示例。界面来自 [Shadcn Admin](https://github.com/satnaing/shadcn-admin) 的 Tasks 页面，按 MIT 许可提取基础组件，并适配为六项中文产品发布任务。

## 先体验一个真实可复现的问题

你准备发布 Agent Notes 1.0，落地页、截图、演示视频等事项都列在工作台里。

1. 点击“只看待处理”。
2. 检查表格，已经完成的“GitHub 项目”仍然出现。
3. 这就是要交给 SuperAgent 修复的问题：只显示还没完成的任务，搜索、状态与优先级筛选仍应正常。

这是教学副本故意保留的问题，不代表上游 Shadcn Admin 存在同样的缺陷。账号 A 发任务，SuperAgent 用账号 B 修复并交回 PR，等待人工确认。

修复后的工作台：「只看待处理」不再显示已完成事项；工具条还新增了「生成发布清单」，用法见下方「使用说明」。

## 在本机打开

需要 Node.js 22.12 或更高版本：

```sh
npm ci
npm run dev
```

打开终端显示的本机地址。页面只有前端，不需要服务器密码、模型密钥、数据库或其他账号。任务状态只在当前页面内变化，刷新会恢复示例数据。

## 使用说明

工作台顶部工具条可以：

- 搜索任务名称或编号，按状态、优先级筛选；点击「只看待处理」只显示还没完成的任务，三种筛选仍可叠加使用。
- 点击「生成发布清单」，工具条下方会在本页列出所有未完成事项及其负责人、截止时间，可直接点击文本全选后复制给团队。已完成的事项不会列入；如果全部事项都已完成，则显示「已经全部准备好了，可以发布」。

发布清单只在当前页面显示，不会自动发送消息，也不会改动任务状态；任务状态变化后清单随之更新。页面状态仅存在于当前浏览器，刷新会恢复示例数据。

## 检查

```sh
npm test
npm run build
npm run reproduce
```

- `npm test` 验证搜索、组合筛选和单项状态修改，初始版本 3/3 通过。
- `npm run build` 生成可部署的静态页面。
- `npm run reproduce` 单独复现“只看待处理”仍出现已完成事项，初始版本应失败；修复后应通过。它不替代修复时补充的回归测试。
